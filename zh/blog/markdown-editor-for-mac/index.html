Mac 上怎么选 Markdown 编辑器

Markdown 写作2026年10月19日约 5 分钟

好用的 Mac Markdown 编辑器，大致就是笔记以普通 .md 文件放在你自己指定的文件夹里，写的时候能顺手看到渲染结果，公式和图表这类常用的扩展也能正常显示，其余基本是口味问题。真正要选的是三种风格，Typora 这样的所见即所得，Obsidian 这样靠插件撑起来的笔记库，以及妙言或者带预览窗格的代码编辑器这样左边写源码右边看效果的做法。下面先讲怎么挑，再讲几个常见选项，最后说妙言适合什么、不适合什么。

挑编辑器看什么

纯文件还是私有存储

Markdown 本身就是纯文本，最稳的用法是每篇笔记就是普通文件夹里的一个 .md 文件，可以在访达里直接打开，用 Time Machine 备份，用 grep 搜索，哪天想换编辑器也只是换个应用打开同一个文件夹。Obsidian 官网写的是笔记以纯文本 Markdown 文件存在本地。Bear 官网没有说明笔记是数据库还是单个文件，所以如果打算长期用，先试一下它的导出流程再决定。这一条决定了以后迁移有多麻烦，建议放在第一位看。

所见即所得还是源码加预览

所见即所得编辑器里格式边写边渲染，平时几乎看不到语法符号，Typora 官网的说法是真正的实时预览，没有单独的预览窗口和模式切换。源码加预览则是一边敲原始 Markdown，一边看渲染后的页面，前者写起来更顺眼，后者能让你清楚看到文件里到底是什么，贴表格、修坏掉的列表、查某个标题为什么没渲染出来的时候尤其有用。更详细的对比放在 Mac 上的 Typora 替代品 里。

公式和图表

写技术笔记的话主要看三件事，$...$ 公式能不能渲染，Mermaid 代码块能不能渲染，两者是否依赖网络。Typora 官网列出了 MathJax、Mermaid、flowchart.js 和时序图。VS Code 的 Markdown 文档说它内置预览用 KaTeX 渲染公式，也能渲染 mermaid 代码块。妙言的 KaTeX 和 Mermaid 文件都打包在应用里。细节见 Markdown 里写 LaTeX 公式 和 Markdown 里画 Mermaid 图。

同步

Mac 上多数 Markdown 编辑器自己不做同步，只读一个文件夹，文件交给网盘客户端去搬。iCloud 云盘、Dropbox、坚果云，只要能同步文件夹的都行，出了问题也是网盘的问题，能自己去查。也有应用卖自己的同步，比如 Obsidian Sync 提供端到端加密和一年的版本历史，Bear 的 iCloud 同步则被它列为 Pro 功能。要先想清楚自己要的是应用自带的服务，还是一个文件夹。

性能

妙言是 Swift 原生应用，官网说明不带 Electron 运行时。各家编辑器的速度很难靠公开数字来比，最好自己试，把手上最大的一篇笔记在每个候选里打开，在中间敲字看是否流畅。

主要选项

选项 风格 笔记存放 备注
Typora 所见即所得，单窗格 文件 公式用 MathJax，支持 Mermaid，导出格式多，覆盖 macOS、Windows 和 Linux
Obsidian 带插件的 Markdown 笔记库 vault 里的本地 .md 插件很多，Sync 可选付费，官网写的是免费不限量（商用要看它的授权页）

VS Code 代码编辑器，并排预览 文件 内置预览，KaTeX 公式和 Mermaid，没有面向写作的界面

表里厂商的说法都来自各自官网，核对日期是 2026-10-18，价格会变，所以这里不写价格。

想要最干净的所见即所得，并且会在 macOS、Windows 和 Linux 之间切换，选 Typora。想要一个互相链接的知识库，并且不介意自己维护插件，选 Obsidian。想要几乎没有界面的纯文字写作，不需要公式，选 iA Writer。日常就泡在 VS Code 里，笔记和代码放在一起，选 VS Code。

妙言适合什么

妙言是原生的 Mac 本地 Markdown 笔记应用，界面是文件夹、笔记列表和编辑器三栏，在偏好设置（⌘,）里指定存储位置，笔记就是这个文件夹里的 .md、.markdown 或 .txt 文件。分栏模式把编辑区和预览区并排放，按 ⌘\ 切换，也可以在偏好设置里把「编辑模式」设成「分栏模式」。README 解释过为什么不做所见即所得，原生 Swift 做这个很重也难保证稳定，分栏模式能让你一直对着 Markdown 原文写。

内置的有 KaTeX 公式、Mermaid、PlantUML 和 Markmap 图表、带反链的 [[双链]]、每篇笔记的版本历史、自动排版（⌘⇧L）、HTML、PDF 和图片导出、miao 命令行工具，还有把带 --- 分隔符的笔记变成幻灯片的演示模式（见 Markdown 转幻灯片）。没有插件系统，没有的功能没办法自己加。

App Store 买一次就覆盖 Mac、iPhone 和 iPad，三端打开同一个笔记文件夹，比如放在 iCloud 云盘里的那个。Mac 版是 MIT 协议，源码在 GitHub 公开，可以从 App Store 页面 获取，也可以直接看 github.com/tw93/MiaoYan 上的代码。

妙言不适合什么

  • 你想要所见即所得，妙言给不了，Typora 可以。
  • 你想要插件生态、图谱定制或者看板，这是 Obsidian 的地盘。
  • 你需要 Windows 或 Linux，妙言只有 Mac、iPhone 和 iPad，Mac 上要求 macOS 12 及以上。
  • 你需要 DOCX 这类文字处理格式，Typora 官网列了 DOCX 和 EPUB，妙言的导出菜单是 HTML、PDF 和图片，另外还有演示文稿用的 PPT PDF，PDF 能改什么、不能改什么见在 Mac 上把 Markdown 转成 PDF。
  • 你需要完全离线的 PlantUML，妙言会把 PlantUML 文本发到公共的 plantuml.com 服务器去渲染，这点在图表那篇里有展开。

选之前怎么验证

  1. 建三篇笔记，一篇有表格和任务列表，一篇有 $$ 公式和 Mermaid 代码块，一篇有图片。
  2. 在访达里打开这个文件夹，确认每篇都是能直接读的 .md，图片是旁边的普通文件。
  3. 用第二个编辑器打开同一个文件夹，如果两边显示都对，就说明没有被锁住。
  4. 把手上最大的一篇笔记粘进去，在中间敲几个字。

四条都过了，不管选哪个编辑器，都可以放心当作笔记的默认入口。在不同工具之间真正能带走的是语法，所以手边放一份 Markdown 语法速查 是值得的。

常见问题

各个编辑器里的 Markdown 一样吗

核心部分一样，标题、强调、列表、链接和代码遵循 CommonMark。表格、任务列表和删除线来自 GitHub Flavored Markdown，脚注、公式和图表则取决于编辑器，依赖它们之前先实测一下。

妙言能和 Obsidian 或 Typora 一起用吗

可以，它们都能读一个放着 .md 文件的文件夹。同一时间只让一个编辑器在写，避免同步冲突，图片路径先在副本上试一遍。

原生应用就一定更好吗

不一定。原生应用不用带一个浏览器引擎，但更该问的是它能不能渲染你写的语法、文件是不是一直在你手里。妙言没有插件系统，自带什么就是什么。
