把备忘录导出为 Markdown 再交给妙言

笔记管理2026年10月19日约 12 分钟

macOS Tahoe 及更高版本里，「备忘录」可以把一条备忘录存成 Markdown 文件，打开那条备忘录，点「文件」，再点「导出为」或「导出到」，然后选 Markdown。Apple 关于 iCloud 资料归档的支持文章在 2026 年 9 月 17 日的中文版里写的是，Tahoe 及更高版本点「文件」，选取「导出到」或「导出为」，再选 PDF 或 Markdown。Sequoia 及更早版本则只有「导出为 PDF」。得到的 .md 是纯文本。妙言不读取「备忘录」的数据库，它只列出你选定文件夹里的 .md、.markdown 和 .txt，预览里出现的也只是这些文件里真实写下的语法。

在 macOS Tahoe 上导出一条备忘录

这件事是跟着 macOS Tahoe 26 一起公布的。2025 年 6 月的新闻稿说，「备忘录」可以导入和导出 Markdown 文件，2025 年 9 月的新功能列表把这一项写成把备忘录存成 Markdown 文件，或导入 Markdown 格式的文件。

当前 Mac 版《备忘录使用手册》的步骤是这样的。

  1. 打开「备忘录」。
  2. 点要导出的那一条。
  3. 选取「文件」菜单中的「导出为」，再选 Markdown。手册里的英文对应项写作 Export To，同一篇归档文章又把菜单写成「导出到」或「导出为」，界面上出现哪一个就点哪一个，然后选 Markdown。
  4. 需要的话改文件名，也可以加上能在访达里搜到的标签。
  5. 点「保存」。手册这一步用的是「保存」，归档文章结尾写的是「存储」，按钮文案以你当前系统上的对话框为准。

同一本手册还有一条只拷贝选中内容的路。在备忘录正文里选中文字，选取「编辑」菜单中的「拷贝为 Markdown」，再粘贴进一个新的 .md 文件。反过来，把 Markdown 粘贴进「备忘录」，会变成带格式的小标题、列表这一类多信息文本，适合拿来核对你已经写好的文件。

iPhone 上，当前使用手册的写法是打开备忘录，轻点共享按钮，再轻点「导出为 Markdown」，如果没看到这个选项，先轻点「查看更多」按钮，然后选取发送或保存备忘录的方式。iOS 18 那一版同一页只有 PDF、「在 Pages 文稿中打开」和打印，没有「导出为 Markdown」。把 .md 导入「备忘录」是相反方向，支持文章写明从 macOS Tahoe 26、iOS 26、iPadOS 26 起可用，Mac 上的菜单是「文件」里的「导入 Markdown」，导入结果放在名为「导入的备忘录」的文件夹里。

导出步骤写的是一条备忘录，没有写「把整个文件夹一次导出」这种命令。文件夹是导入那边才有的说明，「文件」里的「导入至备忘录」可以选文件夹，勾选「导入时保留文件夹结构」会留下原来的层级，找不到这个选项时先点「选项」，支持文章里的说法是「显示选项」。导出时保存位置由你自己选，.md 落在哪个文件夹，就是保存对话框里选的那个。

Sequoia 和更早系统实际能做什么

macOS 15 的《备忘录使用手册》写的是，用「文件」里的「导出为 PDF」导出 PDF，或用「文件」里的「在 Pages 文稿中打开」把备忘录打开成一份 Pages 文稿。这份文稿会保留项目符号、缩进和粗体这一类格式，而且是另一份拷贝，「备忘录」里之后的修改不会回到 Pages 文稿。那一版导出页有 PDF 和 Pages，没有 Markdown 命令。

内容不长的备忘录，直接在 Markdown 里重写往往比找转换器省事。若是涂鸦、扫描件、表格和照片也要变成文件，Obsidian 的 Importer 插件走的是另一条路，它不用 Apple 的 Markdown 菜单，而是在 Mac 上读取「备忘录」的数据。在 Obsidian 里打开 Settings，从 Community Plugins 安装 Importer 并启用，打开插件，File format 选 Apple Notes，再选 Import。弹出的打开面板标题是 Select the "group.com.apple.notes" folder to allow Obsidian to read Apple Notes data。看过生成的模板和预览之后，再选一次 Import。Obsidian 的帮助写明，这一路能带上表格、图片、涂鸦、扫描件、PDF，以及 iOS 17 引入的链接。带密码的备忘录在解锁前会被跳过，因为 Apple 对它们做了加密。扫描件会变成未裁切的图片、裁切后的图片或 PDF，取决于是哪一个系统创建或编辑的。这个插件目前只在 macOS 上，iOS 版还没有。它写出的是普通 Markdown 文件夹，之后把妙言的笔记位置指过去即可。Obsidian 自己的语法在妙言里会剩下什么，写在 Mac 上更轻的 Obsidian 替代品。

iPhone 上的「在 Pages 文稿中打开」也能看出哪些对象经不起换格式，哪怕你已经有了 Markdown 导出。当前 iPhone 手册说，涂鸦不能在 Pages 文稿里编辑，扫描文稿和 PDF 会显示成缩略图，标签、提及、核对清单和指向其他备忘录的链接在那边不是有效项目。导出 PDF 时用的是备忘录附件当前的显示方式，多页 PDF 或扫描文稿只会带上第一页。这是 Pages 和 PDF 的说明，不是 Markdown 的规格，但它解释了为什么一份纯文本导出必须把其中一部分压平或丢掉。

预览为什么只认文件里的字

「备忘录」存的是多信息文本，Markdown 是一份靠 #、-、| 这些字符表达结构的文本文件。Apple 的导出页面写了命令和文件类型，没有公布核对清单、表格、附件、涂鸦各自会变成哪一种 Markdown。把 .md 当文本打开，读里面的字符。

这篇文章依据的是妙言 V4.5.0。它用 cmark-gfm 解析这段文本，打开的扩展是 table、footnotes、strikethrough 和 tasklist。核对清单要变成复选框，行本身得是任务列表，未完成写成 - [ ]，已完成写成 - [x]。表格要显示成表格，文件里得有 GFM 表格，包含表头行和分隔行。具体语法，以及分隔行对不齐时整块会留成纯文本的情况，在 Markdown 语法速查 里。涂鸦、扫描件或 PDF 要在预览里出现，导出结果里得有对应文件，并且笔记用链接指过去。如果 .md 里涂鸦原来的位置只剩一句话，预览没有别的东西可以画。

图片通常是要改路径的那一部分。妙言在你粘贴图片时，会把文件写到这条笔记所在文件夹里的 i 目录，并插入 ![](/i/filename) 这种链接，其他文件放进 files，前缀是 /files/。预览解析 /i/... 时，基准是笔记所在的那个文件夹。没有前导斜杠的相对路径，比如 attachments/photo.png，也是相对这个文件夹。以 / 开头、又不是 /i/ 的路径，预览会当成磁盘上的绝对路径，所以图片链接写成 /files/photo.png 时，预览找的是磁盘根上的 /files/photo.png，不是你的笔记文件夹。

GitHub 对同一串字符的读法不一样。它的文档说，链接相对当前文件，以 / 开头的链接相对仓库根目录。/i/photo.png 在妙言里指向笔记旁边的图片，在 GitHub 上则去仓库根目录找 i/photo.png。这些笔记如果还要在 GitHub 上看，用 i/photo.png 或 attachments/photo.png 这种相对路径，两边会指向同一个文件，前提是图片就放在笔记旁边、路径所写的那个位置。

把文件放进妙言打开的文件夹

如果笔记本来就在一个文件夹里，做法见 本地优先的 Markdown 笔记怎么管，把导出的 .md 拷进这个文件夹，图片也按链接所指的位置一起拷过去。妙言用 macOS 的文件系统事件监听这个文件夹，新的 .md、.markdown 或 .txt 会出现在列表里，这种拷贝不需要重启。

如果这次导出的文件夹就要当成笔记库，把它设成笔记位置。打开「妙言」菜单里的「偏好设置…」（Command-,），停在「通用」，点「笔记位置」旁边的「更改」，选中文件夹。妙言会先确认它是可写目录，检查失败时提示标题是「无法使用这个文件夹」，原来的位置保持不变。提示正文会说明是读不到还是写不进，读不到时是「妙言无法读取这个文件夹。如果这是云盘目录，请打开云盘应用，确认该文件夹已在访达中可见。」写不进去时是「妙言无法写入这个文件夹。请选择可写文件夹，或在云盘应用中开启离线访问。」检查通过之后，会弹出「重新启动妙言后生效」，点「确定」会重启应用，点「取消」会把位置退回上一个。这个文件夹要不要再用 iCloud 云盘或其他服务同步，是另一件事，写在 跨设备同步 Markdown 笔记的几种做法。

和妙言自己保存图片时一致的目录大致是这样。

Inbox/
  Meeting notes.md
  i/
    photo.png

笔记里对应的写法是 ![photo](/i/photo.png)。侧边栏会跳过名为 i、files、assets、.cache、.Trash 的文件夹，也会藏起那种只有附件、没有笔记、也没有子文件夹的目录，文件本身还在磁盘上。如果导出结果是一个 Markdown 文件再加一个全是图片的文件夹，图片文件夹没出现在侧边栏，就是这条规则把它藏起来了。

列表里的标题是去掉扩展名之后的文件名。保存对话框留下的名字不合适，就在访达里改文件名，你打开的笔记就是这个文件。

怎么核对导出结果

先用任何文本编辑器打开 .md，再去看预览。搜 ![ 看图片链接，搜 - [ 看核对清单有没有变成任务列表，看有没有一行竖线和减号，判断表格有没有变成 GFM 表格。这些字符串不在文件里，预览就做不出复选框、表格或图片。

然后再对文件。在妙言里用「在Finder中打开」（Option-Command-R）可以看到笔记文件本身。在访达里，链接写的那张图应该在笔记所在文件夹的相对路径上，如果你把链接改成了 /i/，图就应该在 i 里面。用 Command-3 执行「切换预览」。本地图片找不到时，预览会换成一小块写着 Image Not Found 的占位图。「切换分栏」的快捷键是 Command 加反斜杠，源码和预览可以并排看。

列表里没有某条笔记，多半是这个文件没有被当成笔记。扩展名必须是 md、markdown 或 txt，并且按这个小写形式匹配，.MD 不在列表里。文件要小于 100,000,000 字节，类型得是文本或 Markdown。隐藏文件会被跳过，放在 i、files 或 assets 里面的文件也会被跳过。如果改了「笔记位置」之后点了「取消」，应用读的仍是原来的文件夹。

什么时候不该导出成文本

还要当文稿用的涂鸦、批注过的 PDF、扫描件，更适合留成 PDF，而不是压成一份文本。Apple 的 PDF 导出就是文档里写明的视觉副本，iPhone 上多页 PDF 或扫描文稿只会保留第一页。要在 Mac 上一次把表格、图片、涂鸦、扫描件和 PDF 从「备忘录」的数据里拉出来，文档里写明的办法是 Obsidian 的 Importer。导出之后的文件夹可以用妙言打开，继续按 Markdown 编辑。.md 里没有链到图片的涂鸦，预览里也不会出现。

常见问题

有没有一条命令能导出整个备忘录文件夹？

Mac 使用手册写的是点一条备忘录，再选「文件」里的「导出为」。能选文件夹并保留结构的是导入。要在 Mac 上转换整个资料库，Obsidian 的 Importer 写的是去读「备忘录」的数据文件夹。

打过勾的项目还会保持勾选吗？

导出来的那一行如果是 - [x]，勾还在，未完成则是 - [ ]。如果文件里是一个圆圈字符或一句普通文字，预览就显示这句文字。在妙言预览里点复选框之后如何写回文件，语法速查里有说明。

同一条图片链接为什么在一个应用里能显示，在另一个里不行？

/i/photo.png 在妙言里指向笔记旁边的 i 文件夹。在 GitHub 上，以 / 开头的链接指向仓库根目录，除非笔记文件夹本身就是仓库根，否则这是两个位置。i/photo.png 或 attachments/photo.png 这种相对路径，图片确实放在笔记旁边的对应位置时，两边指向同一个文件。

把文件拷进去之后要重启吗？

拷进已经设为笔记位置的文件夹不用重启，文件监听会把新笔记加进列表。重启发生在更改「笔记位置」的时候，那一步点「取消」会留下原来的文件夹。
