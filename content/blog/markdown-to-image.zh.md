想把一篇 Markdown 笔记变成一张长图，最省事的办法是用能渲染预览并存成 PNG 的应用，在妙言里选中笔记，点「文件」>「导出」>「图片」，整篇渲染好的笔记就会以一张 PNG 存进下载文件夹。没有这样的应用时，也可以先把 Markdown 转成 HTML，再用浏览器截整页，这条路能走通，只是宽度和高度要自己定。不管走哪条路，都先想好宽度，因为长图多数是在手机上看的。

## 在妙言里把笔记导出成图片

在笔记列表里选中笔记，点「文件」>「导出」，会在选中那一行旁边弹出导出子菜单，里面有 HTML、图片、PDF 和妙言 PPT PDF。笔记列表获得焦点、且没开幻灯片模式时，按 `Control + Shift + I` 效果一样，没有选中任何一行就什么都不会导出。

预览如果是关着的，妙言会先打开它，等一秒再导出，导完再关回去。导出时提示条显示「正在导出」和百分比，结束后是「已导出到下载文件夹」或「导出失败」。文件名是 `笔记标题.png`，下载文件夹里已有同名文件时，会在名字后面加上 `_yyyy-MM-dd_HH-mm-ss` 的时间，写不进下载文件夹时，比如在沙盒版本里，会改为弹出存储面板。快捷键、预览开关和命名规则都和 PDF 导出一致，细节在 [Mac 上把 Markdown 导出成 PDF](/zh/blog/markdown-to-pdf-mac/)。

## PNG 里有什么

图片是对实时预览的一次快照，按两倍比例绘制。笔记标题会作为一个 `h1` 加在内容最上面，下面带一条细线，而且每次都会加，笔记本身如果已经以同样文字的 `#` 标题开头，PNG 里标题就会出现两遍，只想要一遍就在导出前删掉笔记里那行标题，目录和标题旁边的锚点链接都会隐藏，表格不再横向滚动，而是铺满正文列宽，所以很宽的表格会被挤成等宽的几列，和 PDF 里一样。

高度就是渲染后整篇笔记的完整高度，只有一张图，不分页，导出代码自己没有设高度上限，笔记很长时导出后拉到最底下，确认结尾还在。

宽度是预览区域的宽度，快照按预览区点数的两倍绘制，Retina 屏上一个点又是两个像素，所以 800 点宽的预览区导出的 PNG 是 3200 像素宽，高度也按同样比例放大。预览区里的正文列宽受「设置」>「编辑器」>「预览宽度」限制，可选 600px、800px、1000px、1200px、1400px 和全宽，默认 1000px。正文列是靠左排的，预览区比正文列宽时，右边会留出一块空白底色。要发手机看的图，可以拖动分隔线把预览区调窄，或者选 600px，导出后看一下右边缘。

颜色跟着应用走，浅色模式是白底加 `#262626` 文字，深色模式是 `#1E1D1B` 底加 `#D6D1C6` 文字。PDF 导出会固定成浅色页面，图片导出不会。

## 会等图表和图片吗

图片、Mermaid 和 Markmap 会等。快照之前，导出会把所有懒加载图片先加载出来，再检查所有图片是否加载完成，以及有没有 Mermaid 块缺少 `data-processed`、Markmap 块缺少显示完成或失败的标记。最多检查五次，每次间隔半秒，大约两秒半之后不管有没有好都会继续导出，所以网速慢的图片或者很重的图表，仍然可能在 PNG 里缺一块。PlantUML 是从 plantuml.com 取回来的图片，按图片算，需要联网。整个导出超过 30 秒会放弃并提示导出失败。

等待条件里没有数学公式。KaTeX 随预览页面一起加载，公式一般到这时已经画好，但公式很多的笔记，导出后还是看一眼结果。三种图表的区别见 [Markdown 里画图表](/zh/blog/mermaid-diagrams-in-markdown/)。

## 其他做长图的办法

### 浏览器整页截图

先把笔记导出成 HTML，用 Chrome 打开，再用开发者工具的设备模式。打开开发者工具，点 Toggle device toolbar，在 More options 菜单里选 Capture a full size screenshot，Chrome 文档把它和只截可视区域的 Capture screenshot 放在一起。宽度就是你在工具栏里设的设备宽度，所以适合做手机比例的图。

问题出在 HTML 本身。妙言导出的 HTML 样式和脚本从 CDN 加载，截图时页面要联网，细节见 [Markdown 转 HTML](/zh/blog/markdown-to-html/)。

### Pandoc 转好再截图

Pandoc 能生成一个不需要联网的页面：

```bash
pandoc -s --embed-resources --css=style.css note.md -o note.html
```

按 Pandoc 手册，`-s` 输出完整文档而不是片段，`--embed-resources` 把脚本、样式和图片用 `data:` URI 放进文件，`--css` 链接样式表，要和 `-s` 一起用。转好后用 Chrome 打开 `note.html`，按上面设备模式的办法截整页。Chrome 的无头模式可以在脚本里跑浏览器，不过它现在的文档只讲了 `--headless` 这一个开关，没有截图参数，临时做一张图，还是开发者工具这条路有文档可依。

## 给手机看的图怎么做

宽度比什么都重要。桌面上舒服的一列字，被聊天应用缩到手机宽度之后字会变得很小，所以导出前先把预览调窄。长句子、宽表格和宽代码块最先出问题。

浅色还是深色看发在哪里。白底在聊天和帖子里是稳妥的默认，不管对方应用是哪种主题都看着一样。图片导出跟着应用外观走，要发到亮色信息流里，先在「设置」>「通用」>「外观」里选浅色再导出。

聊天和社交应用对特别长的图，可能重新压缩，也可能只显示一定高度以内的部分，每个应用不一样，也会变，所以先发给自己或者一个测试群看看。底部被截掉或者字发糊，就把笔记拆成两篇各导一张，或者改发 PDF。

## 常见问题

### 放大能看清楚吗？
快照按预览区点数的两倍绘制，在 Retina 屏上相当于每个点四个像素，放大后文字依然清楚，但对方应用之后怎么处理它就不好说了。

### 文件存在哪里？
下载文件夹，用笔记标题命名。

### 能只导出一部分吗？
导出菜单只处理整篇笔记，想导一部分，就把那部分复制到新笔记里再导出。

### 分享用图片还是 PDF？

图片更容易发，在手机上也好读。PDF 有分页和可选中的文字，打印时更合适，见 [Mac 上把 Markdown 导出成 PDF](/zh/blog/markdown-to-pdf-mac/)。
