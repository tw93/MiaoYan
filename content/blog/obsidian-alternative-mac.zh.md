如果觉得 Obsidian 对你的笔记来说工具太重，妙言是一个更轻的 Mac 应用，打开的是同样的东西，一个装着 Markdown 文件的文件夹。它有三栏笔记库、分栏的编辑与预览、带反向链接的 wikilink、版本历史和 PPT 模式，同时有意不做插件、关系图谱和 Obsidian 额外加的那些链接语法。普通的笔记和最常见的 `[[标题]]` 链接不用转换就能带过来，别名、标题链接和嵌入则需要做一点清理。

## 为什么有人想要更轻的

Obsidian 功能很深。它的文档写到，vault 里有一个隐藏的 `.obsidian` 文件夹，存放快捷键、主题和社区插件，还有一个核心插件 Graph view，用来可视化笔记之间的关系。这些能力正是很多人用它的原因，也是另一些人放弃它的原因，每个设置、插件和主题都是多一样要维护的东西，一个 vault 还可能依赖只有某个应用才认识的插件。

妙言的取舍正好相反。它没有插件系统，官网上的对比说它倾向于提供较少的内置写作功能和本地 Markdown 文件，也没有 Electron 运行时。如果你主要是写、链接和查找笔记，零件少意味着摩擦少。

## 妙言有什么

- **一个文件夹。** 笔记就是你所选文件夹里的 `.md`、`.markdown` 或 `.txt` 文件，见 [本地优先的 Markdown 笔记](/zh/blog/local-first-markdown-notes/)。
- **分栏编辑与预览。** 按 Command 加反斜杠切换，妙言把 Markdown 源码和预览分开，不用所见即所得编辑器。
- **Wikilink 与反向链接。** 支持 `[[标题]]` 链接，反向链接列表放在文档属性面板里，见 [Wikilink 与反向链接](/zh/blog/wikilinks-and-backlinks/)。
- **内置渲染。** 支持 LaTeX 数学公式、Mermaid、PlantUML 和 Markmap 图表、`> [!NOTE]` 这样的 GitHub 风格提示块、任务列表、脚注和表格。
- **版本历史。** 每篇笔记都有快照，见 [Markdown 笔记的版本历史](/zh/blog/markdown-note-version-history/)。
- **PPT 模式。** 用 `---` 分隔把一篇笔记变成幻灯片。
- **命令行工具。** `miao` 提供 list、search、cat、open 和 new，见 [在终端里使用 Markdown 笔记](/zh/blog/markdown-notes-from-terminal/)。
- **iPhone 和 iPad。** App Store 一次购买同时覆盖 Mac、iPhone 和 iPad，都打开同一个 iCloud 云盘文件夹。

## 妙言没有什么

迁移之前先把这些差异弄清楚。

- **没有插件。** 没有插件或主题市场，功能要么随应用发布，要么就不存在。
- **没有关系图谱。** Mac 版源码里没有图谱可视化，关联以反向链接列表的形式出现。
- **Wikilink 只按标题。** `[[笔记|别名]]`、`[[笔记#标题]]` 和块引用都没有实现。
- **没有嵌入。** Obsidian 里的 `![[笔记]]` 和 `![[image.png]]` 嵌入语法，妙言源码里没有对应的解析处理。
- **插件里或 `.obsidian` 里的 Obsidian 专属功能。** 存在快捷键、主题或插件设置里的东西都会留在原地。

如果你依赖其中任何一项，妙言就不是直接替换，继续用 Obsidian 是对的。两者也可以共用一个文件夹，下面会讲。

## 迁移一个 vault

Obsidian 的 vault 就是一个文件夹，所以迁移主要是让妙言指向它。Obsidian 文档说笔记是 vault 里的纯文本 Markdown 文件，设置存在 `.obsidian` 里。

1. **先复制。** 在访达里复制一份 vault 文件夹，满意之前都在副本上操作，笔记就是文件，拷贝一份就是完整的备份。
2. **让妙言指向它。** 按 Command 加逗号打开偏好设置，点「笔记位置」旁边的「更改」，选择副本，妙言提示重新启动时点「确定」。
3. **看看出现了什么。** 文件夹成为侧边栏文件夹，`.md` 文件成为笔记，隐藏的 `.obsidian` 文件夹会被忽略，因为妙言跳过隐藏文件夹。

### 能带过来的

- 笔记正文、标题、列表、表格、代码、任务列表和脚注。
- 像 `[[项目计划]]` 这样的普通 wikilink，因为妙言按文件名链接，Obsidian 对简单链接也是这样。
- 开头的 YAML front matter。妙言在渲染时会隐藏开头那段夹在两行 `---` 之间的块，文件本身保持原样，Obsidian 的属性本来就是以 YAML 形式写在文件顶部，所以不会受影响。
- 标准 Markdown 链接和图片。
- `> [!note]` 形式的提示块。妙言认得五种标记（`NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION`），大小写都可以，Obsidian 的其他类型比如 `[!faq]` 不认识，会按普通引用显示。

### 带不过来的

- **别名、标题链接和块链接。** 在妙言里，括号之间的全部文字会成为要查找的标题，所以链接指向的是一篇不存在的笔记。可以这样找出来：

```bash
rg -n --glob '*.md' '\[\[[^]]*[|#^]' .
```

  把每一处改成纯标题链接或普通 Markdown 链接。
- **嵌入。** 用 `rg -n --glob '*.md' '!\[\[' .` 找出 `![[...]]`，换成普通链接或标准图片。
- **图片。** 妙言要求图片写成 `![name](/i/name.png)`，文件放在笔记所在文件夹的 `i/` 目录下，Obsidian 风格的图片引用需要转换，文件也得移过去。
- **插件内容。** 为社区插件写的代码块会被当作普通代码或纯文本渲染。
- **不同文件夹里的同名笔记。** 在妙言里指向重复标题的链接会发起搜索，而不是直接打开某一篇，所以要把重名的改掉。
- **设置。** 快捷键、主题和插件配置不会迁移。

### 两个一起用

两个应用读写的是同一套文件，所以可以让 Obsidian 处理需要插件的笔记，同时在妙言里打开同一个文件夹快速阅读和写作。避免在两边同时编辑同一篇笔记，如果妙言打开着某篇笔记而别的应用改了它，妙言会从磁盘重新加载，并把你没保存的改动备份到 `.miaoyan-conflicts`，不过日常最好别依赖这个。

## 公平地比一比

| | Obsidian | 妙言 |
| --- | --- | --- |
| 存储 | Markdown 文件夹（vault） | Markdown 文件夹 |
| 插件 | 社区插件 | 无 |
| 关系图谱 | 核心插件 | Mac 版没有 |
| 链接语法 | 带别名、标题、块的 wikilink | 按标题的 wikilink |
| 嵌入 | `![[note]]`、`![[image.png]]` | 没有 |
| 编辑 | 此处不比较 | 源码编辑加分栏预览 |

Obsidian 一栏基于 2026-10-18 查阅的帮助页，妙言一栏来自 README 和源码，两边的价格与许可协议随时可能有变，直接看各家官方页面即可，不要以此表为准。

## 什么时候留在 Obsidian

如果你用了无法替代的社区插件，靠图谱来思考，依赖嵌入和块引用，或者要在妙言不支持的平台上工作，就留下。如果你想要一个不碍事的原生 Mac 应用，笔记库只是文件，就迁过来。

Mac 版在 [GitHub](https://github.com/tw93/MiaoYan) 开源，[App Store](https://apps.apple.com/app/id6759252269) 版本一次购买覆盖 Mac、iPhone 和 iPad。

## 常见问题

### 不转换可以直接用妙言打开 Obsidian vault 吗？

笔记本身可以，文件夹原样打开，`.obsidian` 文件夹会被忽略，别名、标题链接和嵌入不会生效。

### 妙言会改我的 vault 文件吗？

你打开过的笔记在切换到别的笔记时会被保存一次，即使没改，修改时间也会更新，非 UTF-8 编码的笔记会被存成 UTF-8，所以先在副本上试，妙言不会碰 `.obsidian`，如果需要冲突备份，会在笔记库根目录写一个隐藏的 `.miaoyan-conflicts` 文件夹。

### 妙言有标签或图谱吗？

源码里看不到，笔记靠文件夹组织、靠搜索查找，链接以反向链接的形式显示。

### 还能换回去吗？

可以，笔记始终是同一个文件夹里的纯 Markdown 文件。
