Wikilink 就是把笔记标题写在双层方括号里，比如 `[[项目计划]]`。在妙言里这样写会链接到文件名恰好是这个标题的笔记，被链接的笔记则会把指向它的笔记列为反向链接。好处是链接又短又好读，代价是 wikilink 不属于标准 Markdown，并且妙言只按标题匹配，所以重命名会让链接失效，别名和标题链接也不支持。

## Wikilink 和普通 Markdown 链接

标准 Markdown 链接带一个文字标签和一个目标，比如 `[项目计划](Projects/项目计划.md)`，目标是路径，文件一搬就断，空格还要做 URL 编码，好处是所有 Markdown 渲染器都认。

Wikilink 去掉了路径和标签，写成 `[[项目计划]]`，你只说名字，应用自己去找。把这种写法带火的 Obsidian 在文档里也讲了同样的区分，wikilink 用双层方括号，因为更紧凑所以默认生成，Markdown 链接需要 URL 编码，关掉「Use [[Wikilinks]]」就能切换过去。

| | 普通 Markdown 链接 | Wikilink |
| --- | --- | --- |
| 写法 | `[文字](path.md)` | `[[笔记标题]]` |
| 指向 | 路径 | 标题 |
| 任何 Markdown 查看器都能用 | 能 | 不能，需要应用支持 |
| 移动文件后还有效 | 否，路径变了 | 是，只要标题不变 |
| 重命名文件后还有效 | 只有更新路径才行 | 否，标题变了 |
| 自定义链接文字 | `[文字](...)` | 妙言不支持 |

可移植性才是真正的代价。把同一个文件夹交给不认识 wikilink 的查看器，`[[项目计划]]` 会原样显示成文字，如果要把笔记发布到 GitHub 或静态站点，也得先转换。

## 在妙言里怎么写

在双层方括号里写笔记标题，不带 `.md` 扩展名：

```markdown
下一步见 [[项目计划]]，背景见 [[会议记录 2026-10]]。
```

标题是去掉扩展名的文件名，所以 `项目计划.md` 对应 `[[项目计划]]`。匹配是精确的，大小写有区别，多一个字符也会失败。妙言的 Agent skill 也是这个要求，目标文字要和笔记标题保持一致，不要自己发明别名、标题或块引用语法。

这一点和 Obsidian 不一样。Obsidian 文档里有显示文字用的 `[[Example|Custom name]]`，链接到标题的 `[[Note#Heading]]`，还有块引用的 `#^block-id`，妙言一个都没有实现，索引把括号之间的全部内容当作标题，所以 `[[项目计划|计划]]` 是指向一篇叫「项目计划|计划」的笔记，而这篇笔记并不存在。

## 妙言是怎么实现的

下面是从源码里读出来的机制。

**一个写法，两份工作。** 编辑器和索引都会匹配 `[[` 与 `]]` 之间的文字，编辑器负责把标题高亮成链接样式，索引则用另一套规则提取不含右方括号的字符，去掉两端空格后作为目标标题。

**索引。** 笔记列表每次刷新时，妙言会用列表里的笔记重建索引，为每个标题记下它指向的标题集合（出链）和指向它的标题集合（入链）。它读的是每篇笔记已经载入的文字，启动后没打开过的笔记还没有载入，所以它里面的链接要等你打开或保存它之后才算数。保存笔记时会更新这一篇的条目。

**点击链接。** Wikilink 会变成 `miaoyan://goto/<标题>` 这样的地址，和 `miao open` 命令用的是同一个 URL scheme。妙言查找标题完全一致的笔记，找到一篇就打开，找不到会提示「请确定你填写的标题是否存在~」并且不会新建，找到多篇时，比如两个文件夹里都有 `会议记录.md`，会以这个标题发起搜索，并提示「发现这里有多个标题，使用搜索能力~」。所以标题唯一不只是整洁，它决定链接有没有歧义。

**预览和导出。** 渲染预览之前，妙言把每个 wikilink 改写成 `[标题](miaoyan://goto/标题)` 这种普通 Markdown 链接，行内代码和围栏代码块里的内容会被跳过，所以代码示例里的 `[[example]]` 仍然是文字。导出走的是同一套处理，所以导出的文件里带着 `miaoyan://` 链接，只有装了妙言的 Mac 上才有作用。

**复制外链。** 笔记的「复制外链」命令放进剪贴板的也是这个地址，可以把某篇笔记的链接贴到别的应用里。

## 反向链接

反向链接回答「谁链接到了这里」。妙言把它显示在文档属性面板里，用 Command Option I 打开，位置在字数和创建、修改日期旁边，显示为「反向链接：」加数量，然后每行一个标题，没有笔记指向它时显示「无」。

列表是纯文本，只告诉你哪些笔记链接过来，不能在列表里点开，需要跳转就用搜索找标题。

## 出问题时怎么查

- **链接打开了别的笔记或者发起了搜索。** 说明有两篇笔记同名，文件名就是唯一标识，把其中一篇改名即可。
- **提示「请确定你填写的标题是否存在~」。** 目标和任何文件名都不完全一致，检查一下大小写、空格和标点，`项目计划.md` 对应的就是 `项目计划`。
- **重命名之后别处的链接失效了。** 妙言在重命名文件时不会联动修改其他笔记里的链接，用搜索框搜旧标题，它会同时查标题和正文，然后逐个改掉即可。
- **反向链接看起来不全。** 索引只统计当前列表里已经载入文字的笔记，也就是启动后打开过或保存过的笔记，打开或保存一下带链接的那篇，反向链接就会出现。
- **为其他应用写的链接显示成文字。** 别名、标题链接和 `![[image.png]]` 这样的嵌入是 Obsidian 的语法，妙言没有处理，改成纯标题或标准 Markdown。

## 什么时候用普通链接

笔记要在妙言之外阅读时，比如 GitHub 仓库、静态站点或 README，用标准 Markdown 链接。个人知识库只在一个应用里使用时，用 wikilink，标题短，写起来快。两种混用也没问题，妙言都能渲染。

## 常见问题

### 妙言的 wikilink 需要写 .md 扩展名吗？

不需要，只写标题，比如 `[[项目计划]]`。

### 支持 `[[笔记|别名]]` 或 `[[笔记#标题]]` 吗？

不支持，括号之间的全部文字都会被当作标题，这些写法无法解析。

### 代码块里的 wikilink 会生效吗？

不会生效，在行内代码和围栏代码块里它们保持为纯文本。

### 有关系图谱吗？

没有，Mac 版不带关系图谱，反向链接以列表的形式显示在文档属性面板里。
