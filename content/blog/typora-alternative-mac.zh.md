在 Mac 上找 Typora 的替代品，先想清楚自己想改的是什么。想继续在同一个窗格里所见即所得地写，就去看别的所见即所得编辑器。想一边看 Markdown 源码、一边在旁边看实时预览，妙言这类分栏编辑器是最接近的替换，笔记本身就是普通的 `.md` 文件，所以可以直接带过去。主要的取舍是放弃在渲染后的文字上直接敲字，换来随时看到文件里到底写了什么。

## 为什么有人想换

Typora 官网自己写了它擅长什么，真正的实时预览，没有单独的预览窗口和模式切换，支持 MathJax 公式、Mermaid、flowchart.js 和时序图、自定义 CSS 主题以及多种导出格式，覆盖 macOS、Windows 和 Linux。人们换工具往往和好坏无关。

- 想看到源码。所见即所得里原始语法是隐藏的，修一个坏掉的表格、一处多余的列表缩进或者一个转义错的字符就更费劲。
- 想在 iPhone 和 iPad 上看同样的笔记。Typora 官网列出的只有桌面平台，妙言的 iPhone、iPad 和 Mac 版在 App Store 里是同一次购买，三端打开同一个笔记文件夹。
- 想要只面向 Mac 的原生手感，以及文件夹、笔记列表、编辑器三栏的布局。
- 想要把笔记直接当幻灯片演示的内置方式，妙言本身就支持，见 [Markdown 转幻灯片](/zh/blog/markdown-to-slides/)。
- 想要开源的 Mac 应用。妙言的 Mac 版是 MIT 协议，源码在 GitHub 公开，Typora 的授权和价格以它的官网为准。

如果这些都不是你的需求，继续用 Typora 完全合理。

## 所见即所得和分栏预览

在 Typora 里你敲字，格式就地出现，窗格同时就是文档，只有一个地方可看。在妙言里你在编辑区写 Markdown，旁边是渲染后的笔记，两边滚动同步。按 `⌘\` 切换分栏，或者打开偏好设置（`⌘,`），在「通用」里把「编辑模式」设成「分栏模式」，`⌘3` 会切到整页预览。

妙言的 README 直接解释过这个选择，用原生 Swift 做所见即所得很重也难保证稳定，所以应用保留纯 Markdown 编辑，用同步的视觉反馈来补。这是产品上的决定，而不是以后要修的缺陷，要看它合不合你的写作习惯。

| | Typora | 妙言 |
|---|---|---|
| 编辑界面 | 就地渲染的文字 | Markdown 源码，旁边是预览 |
| 公式 | MathJax，官网称支持大部分扩展 | KaTeX 0.16.0，随应用打包 |
| 图表 | Mermaid、flowchart.js、时序图 | Mermaid、PlantUML（公共服务器）、Markmap |
| 平台 | macOS、Windows、Linux | Mac、iPhone、iPad |
| 导出 | 官网列出 PDF、DOCX、EPUB、LaTeX 等 | HTML、PDF、图片、PPT PDF |
| 扩展 | 自定义 CSS 主题 | 没有插件系统 |

Typora 一列来自 typora.io，妙言一列来自应用源码和 README，核对日期都是 2026-10-18。公式引擎的细节见 [Markdown 里写 LaTeX 公式](/zh/blog/latex-math-in-markdown/)，图表的行为见 [Markdown 里画 Mermaid 图](/zh/blog/mermaid-diagrams-in-markdown/)。

## 哪些东西能带过去

两个应用都围着文件转，所以迁移的大半工作就是让新应用指向你的文件夹。

1. **笔记。** 妙言读取你所选文件夹里的 `.md`、`.markdown` 和 `.txt` 文件，打开偏好设置（`⌘,`），把存储位置设成原来的 Typora 文件夹，或者它的一份拷贝。
2. **图片。** 妙言会按笔记所在的文件夹解析相对路径，所以笔记旁边的 `images/photo.png` 能用。它自己的约定是 `i/` 文件夹和写成 `/i/photo.png` 的链接，粘贴或拖入图片时用的就是这个，两种写法可以放在同一个文件夹里。
3. **公式。** `$...$` 和 `$$...$$` 可以直接带过去。KaTeX 支持的是 MathJax 的一个子集，有特殊宏的笔记要打开确认一下。
4. **图表。** 围栏的 `mermaid` 块可以带过去，Typora 的 flowchart.js 块不是 Mermaid，在妙言里不会渲染。
5. **主题。** Typora 的 CSS 主题带不过去。妙言有自己的外观设置，包括跟随系统、浅色、深色，以及字体、预览宽度和代码背景。

迁移先在拷贝上做。挑三篇用了表格、图片和公式的笔记，和 Typora 里的效果并排对一下，再指向真正的文件夹。因为两个应用读的是同一个文件夹，需要的笔记还可以继续用 Typora 打开，只是不要两边同时改同一个文件。

## 它实际是怎么工作的

Typora 把渲染后的视图当作编辑界面，保存时把 Markdown 写到磁盘。妙言把 Markdown 当作编辑界面，再从它渲染出第二个视图。渲染器是 cmark-gfm，带表格、脚注、删除线和任务列表扩展，解析后的 HTML 放进网页视图，由随应用打包的 KaTeX 和图表库去处理。磁盘上的文件就是编辑区里的文字，所以你在编辑区看到的就是保存下来的内容。

不同的渲染器在边角情况上可能不一致，所以要拿自己的笔记去测，核心规则见 [Markdown 语法速查](/zh/blog/markdown-cheat-sheet/)。妙言有一个默认值需要知道，「换行方式」默认是「妙言」，预览中每个换行都会另起一行，如果你的笔记靠空一行才断行，就改成「Github」。

## 出问题怎么办

- **换行看起来不一样。** 检查妙言的换行方式设置。
- **图片不见了。** 相对路径和笔记所在的文件夹对不上了，通常是笔记搬了家，图片文件夹没跟着走。
- **某个公式失败。** 它用了只有 MathJax 才有的功能，改成 KaTeX 支持的写法。
- **怀念在渲染文字上直接敲字。** 这是这次替换的真实代价，先用一个星期分栏模式再决定，确定之前保留 Typora。
- **需要 DOCX 或 EPUB 输出。** 妙言没有提供。

## 在哪里获取

妙言在 [App Store](https://apps.apple.com/app/id6759252269) 上，买一次就覆盖 Mac、iPhone 和 iPad 三个应用，Mac 版源码在 [github.com/tw93/MiaoYan](https://github.com/tw93/MiaoYan)。更全面的编辑器对比见 [Mac 上怎么选 Markdown 编辑器](/zh/blog/markdown-editor-for-mac/)。

## 常见问题

### Typora 的笔记能在妙言里打开吗

可以，只要它们是文件夹里的 `.md`、`.markdown` 或 `.txt` 文件，把妙言的存储位置指向这个文件夹或它的拷贝就行。

### 妙言有所见即所得模式吗

没有，只有纯编辑、分栏和纯预览三种视图。

### 妙言比 Typora 好吗

取决于你想不想看到源码，两者对应的是不同的偏好，拿一份笔记拷贝把两个都跑一遍最直接。
