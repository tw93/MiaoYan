# Preview, export and fonts

- The preview CSS follows the family visual standard (Kata `sumi` skill): quotes are muted text beside a thin warm bar (3px, round ends, `--quote-bar`, starting and stopping with the text, one pixel under the body and 9px from it, as the Weekly and tw93.fun since 2026-11-09; maintainer 2026-10-25, after muted indent alone did not read as a quote) and GitHub alerts a light tint with a coloured title and no stripe; an image passing under the title bar keeps its rounded top corners (`MiaoYanCommon.setupScrollCorners`); nothing glows; transitions ease out at 0.12s for feedback on the control under the pointer and 0.25s for what the page shows, and floating panels fade in place. `VisualRulesGateTests` enforces these, and also that Swift animations take their length and curve from `Theme.Motion` (`feedback` 0.12, `change` 0.25, plus `previewFade` 0.08, a load gate the note switch waits on). The app follows the same standard: text greys come from `Theme.Ink` (primary, secondary, tertiary), which `ShellPalette` and `Theme.Settings` both read; the find bar and the preview TOC share `Theme.FloatingShadow`, and every floating layer (toasts, the find bar, the image preview, the TOC) takes `Theme.Metrics.floatingCornerRadius` (10) on an opaque fill, no `.hudWindow` frost; no interface text is below 12pt (`testListDatesMeetTheTwelvePointFloor` covers the list dates, the one place it slipped), and `PrefsFitTests` keeps every settings row on one line in all five languages.
- Preview images, videos and iframes must stay within `max-width: 100%`. Wide tables may scroll inside `.table-scroll`, but must not widen the page. PDF and PNG exports must fit tables to the output width because exported content cannot scroll. Recheck these bounds when adding raw HTML rendering; verify initial rendering, incremental updates and repeated exports when changing table layout.
- The preview page renders a note once and then changes it in place. `MiaoYanCommon.renderPage()` (common.js) is everything the page does to fresh note HTML, run by index.html at load and by `showNote(html)`, which `MPreviewView.showNoteInPlace` uses to move between notes in preview mode without reloading the template (it falls back to `load` for slides, exports and a changed `previewStyle()`). Live updates go through `patchContent`, which replaces only the top-level blocks whose HTML or inner line layout changed and shifts the source lines of the rest, and the update holds the first visible block in place. A new post-processing step joins `renderPage()` and, for updates, the per-block initialization in `buildUpdateScript`, or notes opened in place or edited live will miss it. Until an in-place switch lands, `note` still names the page on screen; any other update or load cancels it through `loadEpoch`.
- Images reserve their box before they load: local images take their pixel size from the file's header (`PreviewMedia.pixelSize`, cached by path, date and length, skipping undownloaded iCloud files), remote ones the size known from an earlier load (`RemoteImageSizes`). A remote image never seen before asks the app through the `imageProbe` handler, and `RemoteImageProbe` reads the size from the start of the same URL the page loads (a `Range` request for 256 KB, stopped once ImageIO has the size, about 1 KB for a PNG and 8 KB for an iPhone JPEG; an animated WebP's canvas comes from its `VP8X` chunk, which ImageIO does not report) and hands it back to `MiaoYanCommon.applyImageSize`, nearest the view first; the ratio it sets goes once the picture loads, a box above the view grows without moving the text, and only a definite failure (an error status, no size in the range) is remembered for the session. The page still reports the loaded size through `imageSize`, and a probe never replaces it. Lazy images start after the page's `load` event. Until an image has painted it sits on a `--code-bg` tint (`holdImageBox`, `media-pending`) that goes once it loads, breathing toward `--media-pulse` after 0.45s (off under Reduce Motion; the preview CSS allows no gradient, so it is not a sweep), and a remote image never measured, alone in its paragraph, holds a full-width 16:9 box (`media-reserve`) until the probe answers. Every `<video>` is written `preload="none"` with `data-preload` (`PreviewMedia.deferredVideoTags`), because a loading video holds back the `load` event the note waits for; `MiaoYanCommon.prepareVideos` then loads the metadata of those near the view and seeks to the first frame, so the player shows a picture. A note's own `preload="none"` or `poster` is kept (`MediaPlaceholderTests`). `Business/PreviewMedia.swift`, which holds the sizing, the probe and the video tags, imports Foundation and ImageIO only, because the iPhone and iPad reader in MiaoYan-Pro compiles the same file.
- Text carried into an injected script goes in through `HtmlManager.jsStringLiteral`, never a template literal: backticks in the print sheet's comments ended one, and from V4.3.0 the PDF export's setup script never parsed (`testScriptsDoNotInterpolateSwiftTextIntoTemplateLiterals`).
- PNG export must prepare the current DOM, inject export styles and wait for media on every invocation. Cleanup removes those styles, so cached note content never proves a subsequent export is ready.
- Mermaid and PDF export span `Business/HtmlManager.swift`, `Helpers/PdfExportController.swift`, and `Extensions/MPreviewView+Export.swift`. Wait for images and Mermaid rendering before capture. The PDF export prints the preview's own HTML in an offscreen window, which gets no animation frames, nor does a preview behind other windows: `js/frame-fallback.js`, loaded before d3, runs a frame callback from a timer when the native frame does not come, or Markmap's d3 transitions never start and the map prints blank, `index.html` keeps markmap's autoLoader manual so a map that arrives drawn is not drawn again from its SVG's text, and exports wait for `data-markmap-shown`, which goes on only once d3 has no transition left on the map (`fit()` resolves early when another fit interrupts it) (`testMarkmapDrawsAndShowsWithoutAnimationFrames`, `testADrawnMarkmapSurvivesThePageBeingLoadedAgain`). `paginatedPrintCSS()` outranks the preview's rules, so a preview change to quotes or captions is checked in print too (`testAQuotePrintsAsThePreviewDrawsIt`, `testACaptionPrintsBelowItsImage`); a PDF video has no player, shows its poster or first frame, and is hidden if it has neither. PDF headings are `#363433`; a face with no bold of its own (TsangerJinKai W04) takes the regular weight with a 0.25px stroke, because the system's fattened bold printed blurred and heavy, and a face with a real bold keeps it (maintainer's pick from rendered candidates, 2026-11-09; the preview's bold is unchanged).
- `renderMarkdownHTML` in `Business/Markdown.swift` is the single markdown-to-HTML funnel for preview, split view, export, PPT, and actions. Post-render transforms (the GitHub Alerts callout rewrite lives there) belong at the end of that function, never in individual call sites. Alert styling lives in `DownView.bundle/css/typography.css` with dark overrides in `theme-dark.css` (the `.darkmode *` color rule forces explicit dark restatements). The iPhone and iPad reader in MiaoYan-Pro compiles this file too for its alerts, so keep its imports to CMarkGFM, Foundation and MiaoYanCore. Headings keep their text as `id` (in-note links match it, no GitHub slugs, maintainer 2026-11-05) and show a `.heading-anchor` link icon on hover (`base.css`); Mermaid, PlantUML and markmap take the warm paper palette from `js/theme-config.js`; markmap's branch colours are the brand green then the editor's title, link, bold and list colours by depth, read by the patched `render()` in `js/markmap.min.js` and redrawn by `DiagramHandler.retheme` when the appearance changes.
- Frontmatter stripping is a per-surface invariant, not a two-file rule: every surface that outputs note or markdown content (macOS preview/export, appcast/release-notes rendering, any future export) must strip leading YAML frontmatter, and a new rendering surface adds its stripping in the same commit (`---date/image---` has leaked verbatim through the appcast body). `Note.cleanMetaData` calls `Frontmatter.body(of:)` in `Packages/MiaoYanCore`, which the iPhone app uses too, so a rule change is one edit plus `swift test --package-path Packages/MiaoYanCore`. CRLF gotcha: `"\r\n"` is one Swift grapheme, so `range(of: "\n---")` never matches inside it; search both `"\n---"` and `"\r\n---"`.
- Font menus refresh when opened because the preferences controller is reused. Cache classification by the installed family set, not its count, and preserve the selected stored family when rebuilding a menu.
- `Resources/Fonts/MiaoYanMark.otf` holds only 妙 and 言, cut from Source Han Serif SC and renamed MiaoYan Mark because the OFL reserves the name Source for unmodified copies; its copyright and licence fields stay in the file. It is loaded from data and never registered, so it stays out of the font menus. Regenerate it with `pyftsubset` from the OTF in the site's `.fontcache` if the Chinese name ever changes.
- The default editor, preview and interface face is the system pairing (maintainer, 2026-10-11, after comparing it with TsangerJinKai02, Hiragino Sans GB, New York with Songti and Charter with Kaiti): SF for Latin and the system's CJK face for the user's languages, PingFang for Chinese and Hiragino for a Japanese-first user. It is stored as `FontConfiguration.fallbackFont` (`PingFangSC-Regular`); `FontConfiguration.textFont(named:size:)` turns that value, PingFang picked from the popup, or a face that is not installed into `NSFont.systemFont`, whose hidden family still resolves through `NSFontManager`, so the editor's family-based bold and italic keep working, and the preview gets the same pairing from `FontCatalog.fontStack`. TsangerJinKai02 (`TsangerJinKai02-W04`) was the default before that; it is not bundled because redistribution needs a licence from Tsanger (personal non-commercial use is free), installs from that time still store it, and it stays a recommended face with a not-installed row. A stored font choice is never rewritten, not by a migration and not because the face is missing at read time; `ViewController` watches `NSFont.fontSetChangedNotification` and applies a chosen face the moment it appears. The download button opens the foundry's direct `.ttf` URL (`FontCatalog.retiredBundledDownloadURL`); MiaoYan never hosts the file.
- Tracking is one figure, `UserDefaultsManagement.letterSpacingEm` (0.02em), shared by the editor kern, interface labels (scaled by each label's point size) and `.heti` in typography.css. The earlier fixed 0.5pt/0.6pt and 0.04em were tuned in 2022 for LXGW WenKai and spread PingFang and all Latin apart; change the three together.
- Font preferences hold two different spellings. The defaults and fallback in `Business/FontConfiguration.swift` are PostScript names (`PingFangSC-Regular`, and `TsangerJinKai02-W04` in older installs), while every value the font popups write is a family name (`PingFang SC`), because the popups are built from `availableFontFamilies`. Anything comparing a stored value against a default, or matching it to a popup row, has to resolve both sides through `FontCatalog.familyName(forStored:)` first. Comparing the raw strings made the preview's Latin ordering unreachable the moment the user opened the popup, with both states rendering the same selected row.
- `FontCatalog.fontStack(forStored:)` decides who sets Latin, and the test is whether the user picked the face, not whether it is a CJK face. PingFang, the default, has Latin drawn for interface labels and yields it to `ui-sans-serif, system-ui, -apple-system`; a face someone chose leads its own stack and sets the whole line, because TsangerJinKai02 and its like draw Latin to match their Chinese.
- A CSS property's minimum version has to clear `MACOSX_DEPLOYMENT_TARGET`, currently 12.0. When declarations have different minimum versions, retain a supported fallback and verify the absent-variable behavior on both engines.
- The preview keeps the chosen face for bold. Swapping TsangerJinKai02 W05 in for headings and strong text (V4.3.1) made them visibly lighter than the W04 synthetic bold people were used to, and the maintainer asked for W04 back; do not reintroduce a heavier-face substitution. Body text uses `-webkit-font-smoothing: subpixel-antialiased`; `antialiased` on `html` thinned every paragraph in the same release.
- The code font reaches fenced code blocks only (`pre code`, and not inside `blockquote`). Inline code and quoted code inherit the surrounding text face. The stored default is `FontConfiguration.followTextFont`, which means the editor font in the editor and the preview stack in the preview; check `UserDefaultsManagement.codeFollowsText` before treating `codeFontName` as a face. Raw HTML tags in the editor go through `CodeBlockHighlighter.highlightInlineHTML`, never `highlightCode`, which would give them the code font and the `.codeBlock` mark: it sets every tag (opening, closing, self-closing, comments, nested or across lines, but not an autolink or a tag inside a code span) in the editor's own text face and size and the code colour, and leaves text between tags as prose (face picked 2026-10-19 from rendered candidates: the system face two points down read as code beside TsangerJinKai, and the old patterns missed `<video><source></video>` and multi-line `<table>` blocks). Markdown's own punctuation (`#`, `**`, `>`, list markers, link and image brackets, autolink `< >`) takes `NotesTextProcessor.markupFont` (system face, one point down) through `markSyntax` in `MarkdownRuleHighlighter`, because TsangerJinKai draws `<`, `>`, `*` and `"` wide and heavy (maintainer's pick, 2026-09-28). Chinese punctuation stays in the text face's own marks (TsangerJinKai's half-width ones when it is chosen); the maintainer prefers them.
- `ppt.html` loads reveal's stylesheets, not `base.css` or `typography.css`, so none of the `--text-font*` variables reach it. `--r-main-font` is the only one reveal reads. A preview font change is not done until the PPT branch of `previewStyle()` has been checked too.
