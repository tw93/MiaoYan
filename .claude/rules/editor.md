# Editor, menus and localization

- Editor buffer ownership (#543): in preview/presentation/PPT modes `EditTextView.note` follows the list selection while `textStorage` keeps the last edited note, so the two legitimately diverge. `EditTextView.storageNote` records which note the buffer belongs to; every wholesale storage assignment must go through `publishStorage(_:owner:)`, and every whole-buffer persist through `saveTextStorageContent(to:)`, which refuses cross-note targets. Never persist the buffer based on `EditTextView.note` or the table selection alone, and never compare `EditTextView.note` against itself as a guard (that tautology is how the V4.0.0 content-swap shipped).
- Sidebar horizontal layout is owned by `SidebarProjectView.tile()`: after reloads and resizes, the outline frame and first column must match the clip-view width and the clip-view horizontal origin must stay at zero. Do not replace this invariant with event-specific width resets.
- ViewController's local key monitor runs `handleKeyDown` for every key and passes every key on (#491: swallowing them broke Command-C on macOS Tahoe), except Return pressed in the list or sidebar, which it consumes after moving focus so the newline never reaches the editor. Views must not call `handleKeyDown` again from their own `keyDown`, or list shortcuts fire twice.
- Note-list search (`ViewController+Data.swift`) filters by folder scope first, then hands plain `NoteSearchCandidate` values to `NoteContentMatcher` in a detached task, which reads unloaded bodies from disk; the main thread only snapshots and applies results. Never load or lowercase note bodies on the main thread for search, and match titles without the `.md` extension.
- Async note/image/file loading is intentional. Do not reintroduce blocking reads on the main thread for large notes or previews.
- Image upload posts to a local PicGo/PicList HTTP endpoint at `127.0.0.1:36677` (`Helpers/ClipboardManager.swift`). The macOS `Info.plist` ATS permits this via `NSAllowsLocalNetworking`; do not widen it back to `NSAllowsArbitraryLoads`. The markdown preview loads through `loadFileURL` (file://), not a local web server, so ATS does not gate preview rendering.
- Image Upload's `S3 / R2` choice (maintainer 2026-11-26: uploading should not need uPic or PicGo installed) writes pasted and dropped images straight to an S3-compatible bucket from `Helpers/S3Uploader.swift`: a SigV4-signed, path-style PUT to `endpoint/bucket/yyyy/MM/<name>-<8 hex of the content's SHA-256>.<ext>`, then a HEAD of `publicURL/<key>`, and the note links that only when it answers 2xx. The hash is there because a dropped file keeps its own name and the local copy goes after upload, so `image.png` alone let the next one overwrite the first in the bucket; the HEAD because the local copy is trashed after the swap, so a wrong public URL must fail before it (both found in review before release). It shares the PicGo branch of `ClipboardManager.saveClipboard` (local link first, swapped and the local file trashed only after the note points at the upload), and so do uPic and Picsee since 2026-11-27: they put an `uploading-…` placeholder in and trashed the local file whether or not the swap found it (`testAnUploaderAppKeepsThePictureWhenTheLinkChangedMeanwhile`, which runs a stand-in uPic through `ClipboardManager.appUploaderExecutable`). Logged errors carry the S3 error code, never the response body, which can name the access key id. The sheet asks for four things, the ones R2's dashboard shows (maintainer 2026-11-27, simplest form): the bucket's S3 API address, the two keys and the public URL. The bucket is the address's first path segment (R2 shows it with the bucket at the end) or the labels before `s3` in an Amazon host, and the signing region is `auto` on R2, a region-shaped label after `s3.` or `s3-` (Amazon, Backblaze, Wasabi), else `us-east-1` (MinIO); a store whose region is elsewhere in its host and that refuses `us-east-1` cannot be used, the price of no Region field (`testTheBucketComesFromTheAddress`, `testTheRegionComesFromTheAddress`). The secret key lives in the Keychain under `<bundle id>.s3-upload`, so a `com.tw93.miaoyan.qa` build or a test never touches the daily app's; the other fields are `s3Upload*` defaults, written only after the Keychain took the secret, so a refused save leaves the settings before it whole, and the settings row reads the host from the defaults without a Keychain read (`S3UploadSettings.publicHost`). Save stays off for plain `http` to anything but this Mac or the local network (`S3UploadConfig.isLoadable`: a name with no dot, `.local`, loopback and the private and link-local address ranges; a public IP address is refused although ATS would let it through, since the picture would cross the internet in the clear): ATS allows local networking only, so such an address was saved and then failed on every paste. A bucket's refusal and a public URL that does not serve the image each have their own toast (`UploadError.toast`), since the plain "Upload failed" left a first setup with no hint which field was wrong. The sheet's four labels stay in English in every language, as R2's dashboard names them. `S3UploaderTests` checks the signer against AWS's published SigV4 examples; an end-to-end check can run against `rclone serve s3 --auth-key KEY,SECRET`, which verifies signatures.
- `Helpers/TypographyCleaner.swift` (Edit → Clean Typography) must never rewrite protected regions: fenced/inline code, math, link targets, wikilinks, bare URLs, frontmatter. Extend the segment parser, don't bypass it. `Helpers/HtmlToMarkdown.swift` converts pasted HTML only when block-structure tags are present, so plain-text paste stays authoritative for code copied from editors; keep that gate.
- Every `.lproj` must be listed in the five `PBXVariantGroup`s (`Main.storyboard`, `Localizable.strings`, `Localizable.stringsdict`, `InfoPlist.strings`, `ContentViewController.xib`), or the folder never reaches the bundle: Spanish was contributed in 2026-03 and shipped nowhere until it was registered on 2026-10-23. Spanish has no row in the language popup and appears only through the system language, where the popup still reads English.
- New macOS menu items need the storyboard entry plus an ObjectID-keyed `.title` line in all four `Main.strings` (es/ja/zh-Hans/zh-Hant); new toasts need the English text as key in all four `Localizable.strings` (Base has no Localizable.strings, English falls back to the key itself). Missing a file silently ships English to that locale. Changing a toast's English text makes a new key: each language is translated again from the new English, not carried over from the old key, which left zh-Hant, ja and es on the old wording three times (2026-10-23, 11-06, 11-27).
- Copy in the editor (`ClipboardManager.handleCopy`): one heading line copied on its own (the caret on it, or a selection from the line start that stays on it, as a triple click makes) gives the words without the `#` marks; a selection that runs past the line, a `#` line inside a fenced code block and Cut all keep the Markdown as written, so a heading moved by cut and paste stays a heading (maintainer, 2026-11-16). The preview already copied a lone heading without marks (`MiaoYanCommon.selectionPayload`).
- A file or picture dropped on the editor goes after the line it was let go on, on a line of its own, and never splits that line (`ClipboardManager.beginDroppedLine`, maintainer 2026-11-26); let go inside a table, a quote, a fenced code block or a `$$` formula, it goes after the whole block (`DropPlacement` in MiaoYanCore, which the iPad editor uses too; code is told by the scan the table commands use, `TableEditing.codeBlockEnd`, so a fence of tildes and one indented under a list item count): a line holding text gets a line break first (CRLF in a CRLF note, `ListContinuation.lineBreak`), two after a table or a quote, since cmark-gfm takes any line right under a table for one more row and one right under a quote for more of it (the first version put the link there with one break and a test held the wrong text, found by the 2026-11-27 release review); an empty line takes the link as it is, with a break on the side where the next line holds text, so the empty line that kept two paragraphs apart still does (`DropPlacement.spot`); an empty line inside code is code and sends the link after the block, a line of spaces alone gets a break first (the link would be indented into code), and an empty line above an indented line stays as it is, since that line is more of a list item and an empty line around the link would end the list (all three found by the review of the first fix). The iPhone editor still asks `lineEnd` alone and has to move to `spot` to leave the same empty lines. Promised files and bare picture data land the same way; one undo takes the whole drop back, and a drop that puts nothing in takes its line break back, judged by the text's length since `saveFile` answers true for a picture it could not write, and a file whose copy fails later takes the breaks on both sides out with its link (`droppedLineBreak`, and the one `endDroppedLine` wrote after it). A plain line right under a quote's paragraph is more of the quote (a lazy continuation), so a drop on either goes after both; a line that opens a heading, list, code or table is not. A paste still goes in at the caret, which the writer placed. The iPhone and iPad editor places a dropped picture the same way.
- The title field has its own field editor (`TitleTextFieldCell` hands out a `TitleFieldEditor`; the storyboard sets the cell's class), so text arriving by any route (Command-V, Edit > Paste, the context menu, a drop) passes one filter: text with line breaks keeps its first non-empty line, without the `#` marks when that line is a heading, and the clipboard is never rewritten. The shell's title field does the same through `ShellModel.singleLineTitle(_:was:)`. A title longer than a file name holds (`Note.fileNameFits`, 255 UTF-8 bytes with the extension) is refused with a toast before a rename is tried, in every rename entry point, and an alert that quotes a title cuts it with `MiaoYanAlert.shortTitle`: a whole note pasted into the title once became a rename that failed and an alert taller than the screen (I-56).
- A table is edited as text, with keys (`TableEditing` in MiaoYanCore; reader feedback 2026-11-20 that typing a table pipe by pipe kept them on Bear, and no WYSIWYG table, as #454 was answered): Tab and Shift-Tab move between cells and select the cell's words, Tab in a row's last cell goes on to the next row, Return goes to the first cell of the next row, both add a row after the last, and Return on a last row left empty hands the line back, as it does for an empty list item. Shift-Return, and Return before a row's first pipe, stay plain line breaks. Format > Table adds and removes rows and columns and aligns a column; its items go to the first responder and are on only where the command has something to act on (`EditTextView.validateMenuItem`). `EditTextView.keyDown` asks `TextFormatter.tableEdit` before the indent and list paths, so every Return and Tab in the editor passes through `TableEditing.locate`: it must stay cheap (it reads outward from the caret, never from the top of the note) and must hand back nil for anything that is not a table, which then keeps the old keys: prose with a pipe, a table inside a quote, a selection across lines, a fence of backticks or tildes, four columns of indent (counted from the content column when the table sits under a list item, which then is a table like any other), a `$$` formula. A row with no line of dashes under it yet is taken for a table only when pipes close it at both ends around two cells or more, so `|x|` and `|a| + |b|` stay text. `testNoCommandLosesTextOrLeavesTheTextOnAnyInput` runs every command at every offset of 400 made-up texts; a line ending in `[[` trapped the first version, found in review before it shipped. Only spaces and tabs are trimmed from a cell. Every command writes the table the way Format (Prettier) prints it, columns padded to their widest cell with a wide character counting two and `---` the narrowest, and `testFormatLeavesATableTheKeysTidiedAsItIs` keeps the two agreeing: change the padding in one and each undoes the other. A row is cut where cmark-gfm cuts it, at every pipe without a backslash, code spans included, except inside `[[note|label]]`, where padding would break the link. The edit replaces only the text that changed, so a move in a tidy table moves the selection alone.
- The quick-input templates (`/table`, `/markmap`, `/mermaid`, `/plantuml`, `/fold`, `/task` plus Tab, in `ShortcutTemplateManager`) take their placeholder words from `Localizable.strings` in the interface's language; until 2026-11-21 an English, Japanese or Spanish interface got 列1, 主题 and 开始 (maintainer's call that day). The Chinese words are the ones the templates always had, so nothing changes there. `/table` is written through `TableEditing`, which makes its dashes and empty rows as wide as the headers in any language (`testTheTableTemplateIsTidyInEveryLanguage`). A new placeholder needs a key of its own: `End` already means 结尾 elsewhere, so the last box of the Mermaid template is `Finish`.
- A table is drawn as a table without a character of it changing (`TableColumnAligner`, maintainer's pick of two drawn candidates on 2026-11-21: columns lined up, and the pipes and the line of dashes in the quiet markup colour). The editor's face is proportional, so the spaces that pad a cell in the file do not line the pipes up; every column takes the width of its widest cell, and the `.kern` of the spaces around each cell is raised or lowered until the pipes stand under each other, a column marked `--:` or `:-:` moving its words right or to the middle. Widths come from the words, not from the padding, so an untidy table lines up as well and the result never depends on how many spaces the file holds: the first version padded to the widest padded row, which made a table wider than its text and wrapped every row in a narrow editor. A table wider than the editor is left as typed (aligned, all its rows would wrap at the same place, worse than one long row wrapping), and looked at again when the editor's width changes (`followWidthForTables`); so are a table past 300 rows and one holding a tab or an image. `TableEditing.layouts` in MiaoYanCore names the tables and where their cells start, read in one pass for a whole note and for the run of pipe lines around an edit otherwise, and `testTheLayoutsAreTheTablesTheKeysEdit` keeps them the tables the keys edit. The storage delegate calls it after the highlighter on every edit: a keystroke in prose may only look at the lines above and below, and one in a table goes over that table's rows (measured widths are kept by row, and only spacing that differs is written, so the other rows are not laid out again). The characters it touched carry `widenedKey` and `quietKey`, which is how the spacing and the colour are handed back when the lines stop being a table; `applyEditorLetterSpacing()` writes `.kern` over the whole note, so a call to it is followed by `TableColumnAligner.alignAll`. Not done: the iPhone and iPad editor.
- A long list item wraps under its own words, not under the dash (`ListHangingIndent`, maintainer's call on 2026-11-21 after reader feedback on 2026-11-17): a paragraph that starts with a list marker (`-`, `*`, `+` or `1.`, with its indent, an optional task box and the space after) gets a `headIndent` of the marker's drawn width; prose, a dash inside a code block and a line that loses its marker keep or get back an indent of 0. Only the paragraph style changes. It runs after the table pass in the storage delegate, on the edited paragraphs while typing and on the whole note after a full scan, and `ListHangingIndent.drawStructure` runs both passes after `updateParagraphStyle` and `applyEditorLetterSpacing`, which write the plain style and spacing over every paragraph. `ListHangingIndentTests` measures where the second line of each kind of item starts on screen.
